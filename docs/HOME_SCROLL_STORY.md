# Packet & Path 首页滚动叙事实施路线

记录日期：2026-08-02；版本状态复核：2026-08-25

- 版本 01：`blog-version-01` / 本地维护环境
- 版本 02：`blog-version-02` / 线上内容对齐环境
- `master`：GitHub 与生产发布基线

当前站点实现基线：版本 01、版本 02 与 `master` 均以 `eb145998…` 为共同站点源代码基线，都采用本文记录的五阶段滚动叙事方案并包含 F5 DNS 故障复盘。版本 02 可在该基线之上带有不改变站点页面的本地文档维护提交，因此分支尖端不必永久相同。本文中的“版本 02”描述保留为这套首页最初的设计来源，不再表示它是独立实验分支。

## 目标

最初在版本 02 中把首页从“首屏动画 + 现场笔记静态屏”重构为一段由纵向滚动驱动的网络工程叙事；该实现现已进入两个版本环境。页面仍使用正常滚动，但核心舞台会暂时固定在视口中；用户的滚动距离直接控制动画时间轴，停止滚动即停止动画，反向滚动即反向播放。

参考视频的形式语言只用于启发交互机制，不复制其主题与素材。最终视觉必须属于网络工程师的个人博客：路由、数据包、节点、链路状态、故障诊断、收敛与恢复是所有结构和动效的依据。

## 设计系统

- 主背景 `#06131c`：网络控制平面深蓝黑。
- 抬升背景 `#0a1d28`：监控面板与路由舞台。
- 主信号 `#8de7ed`：健康链路、可观测状态和数据包。
- 决策信号 `#ffb45b`：下一跳、收敛过程和关键节点。
- 故障信号 `#ff6f61`：链路异常、丢包和告警。
- 内容背景 `#dfe8e8`：动态故事结束后的现场笔记内容层。
- 展示字体继续使用窄体工业无衬线，数据与标签继续使用等宽字体。

唯一的标志性元素是“持续存在的网络拓扑”。它承担参考案例中人物或三维物体的视觉锚点角色，并在不同阶段完成位移、放大、穿越、故障和恢复。

## 五阶段时间轴

### 00 建立连接

- 保留 `Packet & Path` 主标题和当前路由拓扑。
- 节点上线，链路显现，轻量环境动画维持“系统在线”的状态。
- 拓扑仅保留节点、链路和数据包，移除外围监控标签与装饰性数值。

### 01 数据包进入

- 标题退出主要视野，拓扑向视口中心移动并适度放大。
- 数据包从 Origin 经过 Access 前往 Core。
- 出现与该阶段对应的说明文字。

### 02 穿越核心

- Core 节点成为镜头中心。
- 同心环放大形成“穿过核心节点”的隧道过渡。
- 只使用 SVG、遮罩、缩放和透明度，不引入无必要的三维引擎。

### 03 故障与诊断

- 主路径转为故障色并在指定位置中断。
- 故障标记和异常链路依次进入。
- 拓扑保留在画面中，避免退化为一张完全独立的新幻灯片。

### 04 路由收敛

- 备用路径被绘制出来，数据包改道并继续前进。
- 状态从故障色恢复到青色，数据包沿备用路径抵达边缘节点。
- 所有变化由滚动时间轴控制，向上滚动时完整复原。
- 阶段结束后固定舞台直接解除，页面自然进入现场笔记矩阵，不再插入独立交接页。

## 技术架构

- 使用 Astro 保持静态页面输出，不迁移框架。
- 使用 `gsap.timeline()` 建立唯一的桌面端主叙事时间轴。
- 在主时间轴上配置一个顶层 ScrollTrigger：`pin: true`、`scrub`、动态 `end`。
- 使用 timeline labels 表达五个真实阶段，避免用 `delay` 拼接动画。
- 只在顶层时间轴配置 ScrollTrigger，不在子动画中嵌套触发器。
- 主要动画属性限定为 `x`、`y`、`scale`、`rotation`、`autoAlpha`、SVG 描边偏移和少量颜色变化。
- 图片、字体或布局完成后调用一次 `ScrollTrigger.refresh()`。
- 继续复用现有 Astro、Firefly 和 Swup 页面生命周期清理逻辑。

## 响应式和无障碍

- 桌面端使用完整固定叙事，滚动距离约为 4.8 个视口高度。
- 平板和手机保留五个阶段，但将滚动距离缩短到约 4.1 个视口高度。
- 首页默认启用完整的固定与穿越动画，不再因为操作系统的 `prefers-reduced-motion` 偏好自动切换成静态长列表。
- 需要减弱动态时显式使用 `?motion=reduced`，按正常文档顺序展示静态关键状态。
- 不用不可见元素阻挡链接；交互内容在进入最终内容区后保持键盘可访问。
- 导航栏始终保持可见、可读和可操作。

## 性能边界

- 不在滚动中动画修改宽高、外边距、定位坐标等高成本布局属性。
- `will-change` 只用于实际参与动画的舞台、拓扑、文案和过渡层。
- 只固定主舞台，不固定整个页面，也不同时建立大量 ScrollTrigger。
- 环境循环动画在舞台离开视口后暂停，并在页面切换时销毁。
- 首版不引入 Three.js；只有未来明确需要可变形三维模型时才评估 WebGL。

## 验收标准

1. 从首页顶部持续下拉时，出现五个可辨识且连续衔接的叙事阶段。
2. 主场景在叙事期间固定，动画进度与滚动位置同步。
3. 停止滚动时主叙事停止，向上滚动时正确倒放。
4. 最终自然进入现场笔记矩阵，原有链接、统计和品牌图标可用。
5. 桌面 2048×960、1440×900 和手机 390×844 均无溢出、重叠或不可读文字。
6. 减弱动态模式能完整获取内容。
7. `pnpm check`、`pnpm type-check` 和 `pnpm build` 通过。

## 本地验收入口

- 常规访问：`http://127.0.0.1:5173/`，默认呈现完整的五阶段滚动动态。
- 兼容完整动态参数：`http://127.0.0.1:5173/?motion=full`，保留用于已有书签和逐阶段验收。
- 显式减弱动态：`http://127.0.0.1:5173/?motion=reduced`，取消固定和穿越动画并展示静态内容顺序。
